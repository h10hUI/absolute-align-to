# Critical Rules

## Verify before answering

- Never answer from memory. When the user mentions logs, files, errors, or data: read the file or run the check **first**, then answer.
- Never guess or assume. If you have not looked, say so and look.
- **When an error occurs, re-read your own edit first.** Confirm the change you made is actually in the file before blaming the environment, config, or CI. The environment is usually right; the edit is usually wrong.

## Do not ask obvious questions

Assume the environment is already set up. 
Check with a tool instead of asking. Focus troubleshooting on code and logs.

## Scope discipline

- Change only what was asked. No drive-by refactors, no unrelated reformatting.
- Match the conventions of the file you are editing.
- Do not commit or push unless asked.
